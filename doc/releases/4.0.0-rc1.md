# UDB 4.0.0-rc1

Date: October 11, 2026. Status: first release candidate, prepared locally.
This is a source release, not a stable release or a published tag.

## Included functionality

- Native indexed persistence in `PERMDATADIR/udb` for the six blocks
  `N`, `C`, `I`, `S`, `L`, `K`, with a global WAL and two checkpoint slots.
- Bounded page caching, configurable per node; the default is 128 MiB.
  Lookups do not require loading an entire block into memory.
- HEL 4 synchronization with mandatory OCL, staged snapshots, origin SID/epoch
  metadata, durable ACK pacing and deterministic authority selection.
- Snapshot promotion preserves existing clients when nickname policy requires
  a Guest rename; internal committed-policy reads do not imply global readiness.
- Explicit rejection of initial client registration while synchronization is
  unavailable, instead of silently waiting for a registration timeout.
- Windows storage support, correct imported-variable access, and a test harness
  that captures invalid-configuration diagnostics without manual dialog handling.

## Deployment requirements

- Declared target: UnrealIRCd `6.2.*`. Compile the canonical `src/udb.c` or the
  standalone `dist/udb.c` against the target server and its dependencies.
- Module version `4.0.0-rc1` does **not** change HEL 4 or storage generation 4.
- No legacy storage/protocol compatibility or automatic migration is provided.
  Back up existing data and use coordinated deployment of the new implementation
  on every UDB node, including an authority/Services implementing the new contract.
  Do not point the engine at legacy text databases and expect them to load.
- DB values use `!n`, `!u<decimal>` and `!s<Base64>`; INF requires origin metadata.
  Legacy value encodings are not accepted. Base64 is encoding, not encryption.
- Use authenticated TLS with certificate verification on each UDB hop and TLS for
  client password commands. HEL negotiation is not payload authentication.
- Readiness requires convergence of all six persistent blocks and a complete,
  current OCL view. An unavailable selected authority may keep a node unavailable
  for new clients; changing the authority is an explicit operator decision.

## Validation and limitations

Earlier development builds passed Linux and native Windows storage, unit,
protocol and configuration checks, including both canonical and bundled modules.
Windows storage benchmarks exercised up to ten million records with 128, 256 and
512 MiB caches. These results are evidence for those builds, not certification
of newly compiled `4.0.0-rc1` binaries.

The release-preparation checks cover metadata version derivation, deterministic
bundle generation, generated-file consistency and source-asset integrity.
The latest initial-registration diagnostic has focused Linux runtime coverage;
its Windows runtime validation and the final rc1 binary build/validation remain
pending. An older intermittent welcome timeout has not been conclusively explained.

No exhaustive Windows validation, empty-OS-cache IRC performance guarantee,
or durability guarantee under power loss is established by these checks.
This candidate contains no prebuilt Linux or Windows binaries.

## Distribution

Local source assets include a complete source archive, standalone `udb.c`,
`modules.list`, these release notes in English and Spanish, a source snapshot
manifest, and `SHA256SUMS`. Verify the sums before building.

The catalog source URL still targets `main`; local preparation does not make
that URL serve this candidate. Committing, tagging, publishing assets and selecting
an immutable published source URL are separate pending operations.

See the [README](../../README.md) and [technical guide](../udb_technical_en.md)
for configuration and the exact protocol contract.
